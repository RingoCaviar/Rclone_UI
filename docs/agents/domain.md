# Domain Docs

This repository uses a single-context domain-documentation layout.

## Before exploring

- Read `CONTEXT.md` at the repository root when it exists.
- Read relevant decisions under `docs/adr/` when they exist.
- Missing domain documents are created lazily when terminology or architectural decisions are actually resolved.

## Vocabulary and decisions

- Use terms as defined by the glossary in `CONTEXT.md`.
- If a required concept is missing, note it for domain modelling rather than silently inventing competing terminology.
- Explicitly flag any proposal that contradicts an existing ADR.
